# 系统架构文档

## 一、整体架构

本项目是一个 **桌面端演出数据采集平台**,采用前后端分离 + Tauri 桌面壳的架构:

```
┌─────────────────────────────────────────────────────────┐
│                    Tauri Desktop App                     │
│  ┌─────────────────────────────────────────────────┐   │
│  │            Vue 3 Frontend (Vite)                 │   │
│  │  - CrawlView: 采集控制                            │   │
│  │  - ShowsView: 数据查询导出                        │   │
│  │  - SettingsView: 系统设置                         │   │
│  └─────────────────┬───────────────────────────────┘   │
│                    │ HTTP (localhost:8756)              │
│  ┌─────────────────┴───────────────────────────────┐   │
│  │         FastAPI Backend (PyInstaller)            │   │
│  │  - /api/crawl: 采集任务管理                       │   │
│  │  - /api/shows: 数据查询 CRUD                      │   │
│  │  - /api/settings: 配置管理                        │   │
│  └─────────────────┬───────────────────────────────┘   │
│                    │                                     │
│  ┌─────────────────┴───────────────────────────────┐   │
│  │          Playwright + Chromium                   │   │
│  │  (随包分发,自动启动真实浏览器)                    │   │
│  └─────────────────┬───────────────────────────────┘   │
│                    │                                     │
│  ┌─────────────────┴───────────────────────────────┐   │
│  │             SQLite (daxi.sqlite3)                │   │
│  │  存储位置: App同级data/ 或 系统用户目录            │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

### 关键约束

- **Local-first 单客户**: 后端只监听 `127.0.0.1`,无多租户、无鉴权
- **固定端口 8756**: 前后端通信端口固定,必须保持一致
- **同时只允许一个采集任务**: 避免有头浏览器冲突
- **单机离线**: 所有数据本地存储,不依赖外部服务(除采集目标网站和可选的打码平台)

### 2.2 核心模块说明

#### 路径管理 (`core/paths.py`)

解决打包后路径不可控的问题,区分三类路径:

1. **只读资源**: 源码在项目里,打包后在 `sys._MEIPASS`
2. **可执行文件所在目录**: 打包后 App 的落脚点
3. **用户数据目录**: 优先 App 同级 `data/`,不可写时回退系统用户目录

**关键功能**:
- `data_dir()`: 自动选择可写的数据目录
- `bundled_browsers_dir()`: 找到随包 Chromium
- `setup_browser_env()`: 设置 `PLAYWRIGHT_BROWSERS_PATH`

#### 爬虫架构

**抽象设计**:
```python
class BaseCrawler(ABC):
    @abstractmethod
    async def crawl_city(self, city_id, max_pages) -> List[RawShowItem]:
        """采集某城市的演出列表"""
        
    @abstractmethod  
    async def enrich_detail(self, items) -> List[RawShowItem]:
        """富化详情(场次/票档)"""
```

**验证码处理流程**:
```
访问列表页
    ↓
检测到验证码
    ↓
DamaiCaptchaSolver.ensure_cleared()
    ↓
├→ 手动模式: 弹出有头浏览器 → 等待人工拖动
└→ 自动模式: 调用冰拓1358 → 失败则回退手动
    ↓
验证通过,继续采集
```

#### 数据流转

```
网页响应
    ↓
parse() → RawShowItem (原始数据,各平台结构不同)
    ↓
normalize() → Show (统一数据模型)
    ↓
ShowRepository.save_batch()
    ↓
SQLite
```

**Show 模型字段**:
- 基础: `title`, `venue_name`, `city`, `category`
- 时间: `start_date`, `end_date`, `show_time`
- 状态: `status` (预售中/正在热卖/演出结束/已下架等)
- 元数据: `source` (damai/maoyan), `url`, `crawled_at`
- 详情: `sessions`, `tickets`, `venue_address`

## 三、前端架构 (Vue 3)

### 3.1 技术栈

- **框架**: Vue 3.5 (Composition API)
- **UI 组件**: Element Plus 2.14 + 自定义 shadcn/vue 组件
- **样式**: Tailwind CSS 3.4
- **构建**: Vite 6
- **状态管理**: VueUse (无需 Vuex/Pinia)

### 3.2 三大视图

#### CrawlView - 数据采集页
- 城市选择器: 热门城市快捷按钮 + 搜索框
- 页数控制: 3页/10页/50页/全部 快捷按钮 + 手动输入
- 实时日志区: WebSocket 或轮询显示后端日志
- 取消按钮: 中止当前采集任务

#### ShowsView - 数据查询页
- 多条件筛选: 数据来源/城市/分类/状态/关键词
- 分页表格: 可排序,点击链接打开原页面
- 批量导出: Excel / CSV

#### SettingsView - 系统设置页
- 验证码模式切换: 手动/自动
- 冰拓账号配置: 账号/密码/余额查询
- 主题色调整: UI 美化

### 3.3 与后端通信

```javascript
// frontend/src/api.js
const BACKEND_PORT = 8756;
const API_BASE = `http://127.0.0.1:${BACKEND_PORT}/api`;

export async function startCrawl(params) {
  return fetch(`${API_BASE}/crawl/start`, {
    method: 'POST',
    body: JSON.stringify(params)
  });
}
```

**注意**: 端口必须与 `src-tauri/src/main.rs` 中的 `BACKEND_PORT` 一致

## 四、打包与分发

### 4.1 后端打包 (PyInstaller)

**入口**: `backend/packaging/entry.py`

**关键配置**:
```python
# .spec 文件
datas=[
    ('configs', 'configs'),           # 配置模板
    ('.venv/lib/.../playwright', 'playwright'),  # Playwright 库
]
binaries=[
    ('ms-playwright', 'ms-playwright'),  # Chromium 浏览器
]
```

**产物**: `backend.exe` (Windows) / `backend` (macOS/Linux)

### 4.2 前端打包 (Vite + Tauri)

**步骤**:
1. `npm run build` → 生成 `frontend/dist/`
2. Tauri 读取 dist/ 作为前端资源
3. 启动内置 HTTP 服务器托管前端
4. 启动后端子进程 (`backend.exe`)

**Tauri 配置** (`frontend/src-tauri/tauri.conf.json`):
```json
{
  "bundle": {
    "targets": "all",
    "resources": [
      "../dist",
      "../../backend/packaging/dist/backend*",
      "../../backend/ms-playwright"
    ]
  }
}
```

### 4.3 自动更新

集成 `@tauri-apps/plugin-updater`:
- 启动时检查 GitHub Releases
- 发现新版本弹窗提示
- 下载并安装更新包

## 六、安全与限制

### 6.1 安全考虑

- **无网络暴露**: 后端只监听 127.0.0.1,不接受外部请求
- **无敏感数据上传**: 所有数据本地存储
- **Cookie 隔离**: 每个平台独立 cookie,不混用
- **打码平台凭证**: 存储在本地 settings.yaml,不进版本库

### 6.2 反爬限制

- **请求间隔**: 爬虫内置随机延迟(0.5~2秒)
- **User-Agent**: 使用真实浏览器指纹
- **Cookie 复用**: 保持会话连续性
- **单任务限制**: 避免并发触发风控
- **有头模式**: 大麦强制有头以便手动过验证码

## 八、已知限制

1. **同时只能一个采集任务**: 有头浏览器独占,多任务会冲突
2. **Windows 安装路径受限**: 装到 Program Files 需回退到用户目录存数据
3. **验证码成功率**: 自动过码依赖第三方平台,识别率非 100%
4. **大量采集风险**: 频繁大批量采集可能触发 IP 限制
5. **macOS 签名**: 未做 Apple 官方签名,首次打开需右键
